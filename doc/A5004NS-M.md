# ipTIME A5004NS-M — what the stock firmware says

Groundwork for a port, taken from `stock-firmware/a5004nm_ml_14_144.bin` (14.14.4)
without opening the case. Nothing here is from a datasheet or a shop listing: the
vendor ships a hardware description file in the rootfs and it is quoted directly.

    dd if=a5004nm_ml_14_144.bin of=kernel.lzma bs=1 skip=64 count=3407872
    python3 -c "import lzma;open('kernel.bin','wb').write(lzma.LZMADecompressor(format=lzma.FORMAT_ALONE).decompress(open('kernel.lzma','rb').read()))"
    dd if=a5004nm_ml_14_144.bin of=rootfs.sqsh bs=4096 skip=$((0x350000/4096))
    unsquashfs -no-exit -d out rootfs.sqsh      # xz, and it needs -no-exit

`out/default/var/run/si/hw` is the file that matters.

## The hardware

| | A5004NS-M | A3004NS-M, for comparison |
|---|---|---|
| SoC | MT7621, 880 MHz | same |
| RAM | **128 MB** DDR2, 16-bit bus | 256 MB |
| Flash | SPI, 16 MB | same |
| Wi-Fi 2.4 GHz | **MT7615**, 11n, 3 streams, 40 MHz | MT7615D, DBDC |
| Wi-Fi 5 GHz | **MT7615**, 11ac, 3 streams, 80 MHz | (same chip, other half) |
| USB | 1 slot, **2.0** | 3.0 |
| Ethernet | WAN=port 0, LAN=ports 1-4 | same |
| Board | IP04346A | |
| Stock kernel | Linux 3.10.108, gcc 4.6.3, built 2022-05-02 | |
| Console | **ttyS1, 57600 8n1**, root on mtdblock5 | 57600 |

**Two MT7615, not one.** `out/default/etc/wireless/l1profile.dat` gives INDEX0 =
MT7615 at EEPROM offset 0x0 (2.4 GHz, ra0) and INDEX1 = MT7615 at 0x8000 (5 GHz,
rai0). So the mt76 DBDC patch this tree carries for the A3004NS-M is **not needed
here** - each radio owns its band. The 65 DBDC strings in the stock kernel are the
driver supporting the feature, not this board using it; the profile is the evidence
and the string count was not.

## GPIO, from the vendor's own file

    cpu_led      18   active low
    wl_led 2.4G  17   active low
    wl_led 5G    14   active low
    usb_led       7   active low
    reset button  4   active low
    wps button    3   active low

Almost identical to the A3004NS-M, which frees the same pins - and GPIO 14 is the
second WLAN LED the A3004NS-M commit message described as "may well have one too,
but nobody has confirmed it". Here it is confirmed, on this board.

## MAC addresses

`out/default/var/run/si/schema_mac`: one base address with a multiplier of 4, and
each interface derived by adding to byte 6 (the last octet):

    lan   +3
    wan1  +1
    5g    +2
    2g    +0 (no rule)

The same arrangement as the A3004NS-M, where LAN is base+3 and WAN is base+1 - so
`mac-base` with an increment per node should work, and the local bit for 2.4 GHz
still has to be set in `10_fix_wifi_mac` because no device-tree property expresses it.

## What is still unknown

- Partition offsets. The kernel partition ends at 0x350000 (3392 kB) because that is
  where the squashfs starts in the upgrade image, but the flash layout - where
  Bootloader, Config, Factory and the 16 MB device's firmware partition begin - has
  not been read. The stock partition names are Bootloader / Config / Factory /
  Kernel / RootFS / ALL, matching the A3004NS-M's.
- Which EEPROM the two radios are calibrated in. The offsets 0x0 and 0x8000 are
  within a 0x4000-sized region each, named `e2p`, in an nvram zone called RTDEV -
  that is ipTIME's own scheme and needs mapping onto the `factory` partition.
- RAM is 128 MB, which is half the A3004NS-M's. Worth stating plainly for this
  project: the sensor bridge currently uses about 105 MB on the A3004NS-M, so it
  would not fit here with the same margins. As a router it is fine.

## Next step

A DTS can be drafted from the above, using `mt7621_iptime_a6004ns-m.dtsi` as the
starting point rather than the A3004NS-M's - that one exists precisely because it
has derivatives, and this board needs two PCIe radios rather than one DBDC radio.
UART is only needed for the first initramfs boot; 57600 8n1 on ttyS1 is known.
